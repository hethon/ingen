# Tectonic Example

This directory contains a sample `ingen` manifest for [Tectonic](https://github.com/tectonic-typesetting/tectonic), a modernized, complete, self-contained TeX/LaTeX engine.

## Generating the Installers

To regenerate the scripts in the `installers/` directory, navigate to this folder and run:

```bash
bun run ingen installer.manifest.json installers
```

## Upgrading the Installation Experience

Tectonic currently offers its own custom Shell/Powershell installation scripts. However, these scripts have two major UX limitations that `ingen` solves natively:

1. **Automatic `$PATH` Management:** The native Tectonic installers simply drop the executable in the user's current working directory, requiring the user to manually move it to a folder in their `$PATH`. The installers generated by `ingen` automatically detect the user's OS and profile, move the executable to an appropriate location (like `~/.local/bin`), and automatically modify the user's `$PATH` (e.g., editing `.bashrc`, `.zshrc`, or Windows environment variables) so the tool works immediately.
2. **Automatic Binary Aliasing (The V2 CLI):** Tectonic features an opt-in "V2" CLI interface which is activated if the executable is invoked under the name `nextonic`. Rather than requiring the end-user to manually create the aliase, we utilize `ingen`'s `bin_aliases` configuration:
   ```json
   "bin_aliases": {
     "tectonic": ["nextonic"]
   }
   ```
   The generated installer will automatically create a hardlink(on windows)/symlink(on linux) named `nextonic` alongside the installed executable, allowing the user to use both `tectonic` and `nextonic` immediately after installation.

## Known Issues

- **Flat `tar.gz` Archives:** Tectonic's `.tar.gz` files are packaged "flat" (the executable sits at the root of the archive). The current `installer.sh.j2` template attempts to strip a wrapper directory when unpacking. *A future patch will add a configuration option to handle flat archives.*
